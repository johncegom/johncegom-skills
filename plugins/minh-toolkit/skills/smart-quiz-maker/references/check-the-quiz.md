# Check the Quiz

Use this guide when a quiz question or full test might be weak, unclear, unfair, or too easy to guess.

## Check unusual user requests

Try examples like these before trusting the setup:

- `Test me on science.` → Say the topic is very broad, choose a sensible sample, and explain what you chose.
- `Test me on JavaScript Array.prototype.reduce.` → Stay narrow; do not wander into unrelated JavaScript topics.
- `Test me on SQL.` → Start around intermediate if no level is known and adjust from answers.
- `Test my 10-year-old on fractions.` → Use age-appropriate language and situations.
- `Prepare me for a staff-level distributed systems interview.` → Focus on design choices, failure cases, trade-offs, and incomplete information.
- `Test me on spring.` → Ask what “spring” means if the context does not make it clear.
- `Test me on asdfgh.` → Do not invent a topic; ask for clarification.
- `Make it very easy but suitable for a principal engineer.` → Point out the tension and resolve it based on the user's real goal.
- `Test me on why JavaScript is always faster than C++.` → Challenge the false assumption instead of building it into the test.
- `Create a test proving my preferred framework is better.` → Turn it into a fair comparison based on evidence and stated needs.
- `Test me on chapter 7.` when the material is missing → Do not invent chapter content.

## Check each question

Imagine five different learners:

- **Guesser:** looks for wording clues instead of knowing the topic.
- **Memorizer:** remembers definitions but struggles to use them.
- **Half-trained learner:** knows the idea but applies it incorrectly.
- **Experienced learner:** notices context, limits, order of actions, and trade-offs.
- **Skeptical expert:** tries to defend every answer choice.

A strong question should make guessing hard, expose shallow memory, reveal partial understanding, reward practical judgment, and still have one answer that a knowledgeable person can defend as the best choice.

Rewrite a question if:

- two answers are equally reasonable;
- the correct answer is obvious from wording or length;
- the learner needs missing information;
- the question depends mainly on taste or opinion;
- the wrong answers are obviously foolish;
- the scenario tests something outside the intended topic.

## Check the full test

Look for patterns across the whole set:

- Too many correct answers use the same letter.
- One wording pattern keeps revealing the correct option.
- Several questions test the same idea in disguise.
- Earlier questions reveal later answers.
- The test ignores an important part of the topic.
- Difficulty does not change as intended.
- All scenarios sound nearly identical.
- A brand, method, culture, or viewpoint is favored without a reason tied to the user's goal.

Fix these issues before giving the test to the user.
