# Planning Templates

Use these as flexible frames. Preserve another active skill's format in Enhancer Mode.

## Compact standalone plan

```markdown
# <Goal>: Execution Plan

Outcome: <observable end-state>
Evidence: <how completion is verified>
Known constraints: <facts>
Assumptions / estimates: <clearly labeled>

## Scope
Committed:
- <must-fit item>

Stretch:
- <optional if capacity remains>

Deferred:
- <explicitly out of cycle>

## Current execution cycle
Capacity: <stated capacity>
Protected contingency: <amount/range and reason>

| Step | Dependency | Effort | DoD | Commitment |
|---|---|---:|---|---|
| <task> | <dependency> | <range> | <observable evidence> | Committed |

First atomic action: <15–30 minute start>

## Resilience
Bad-day minimum: <2–5 minute meaningful contact>
Rollback trigger: <signal>
Rollback action: <what gets cut first>

## Review
Trigger/cadence: <real trigger>
Replan using: <actual versus estimate + evidence>
```

## Enhancer annotation

```markdown
Planning hardening:
- Capacity fit: <pass/fail + correction>
- Contingency: <protected amount>
- Committed / stretch adjustment: <changes>
- Atomic next action: <small start>
- Risk fallback: <meaningful contingency>
- Replan trigger: <evidence-based trigger>
```

Use inline annotations instead when a separate section would disrupt the domain skill's structure.

## Why-this-choice explanation

```markdown
Problem: <execution pressure>
Choice: <planning intervention>
Why: <why it improves feasibility now>
Why not alternatives: <tradeoff>
Revisit when: <signal that changes the decision>
```
